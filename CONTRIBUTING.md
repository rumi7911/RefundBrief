# Contributing to RefundBrief

Start with the credential-free [judge route](README.md#judge-testing) in a separate local checkout. Use fictional data. Do not call AI providers or send sandbox refunds just to reproduce an interface/reporting issue.

Keep changes focused on the existing source-review and owner-controlled action workflow. Preserve original sources/model outputs, historical reviews, decision snapshots and completed/pending/unknown operations. A quote match establishes provenance, not entitlement. Do not allow the model to choose amounts or bypass owner approval.

Before proposing code changes, run `npm test` and `npm run build`. Add a regression for a reproduced behavioural failure; retain stable operation keys, stale-evidence guards and unknown-outcome blocking. For presentation-only work, check asset/relative links and exact build instructions. Do not imply a fresh CI run or human benefit from a static badge.

For an issue, describe the expected/observed result, reproduction steps, Node/browser versions and whether the fictional demo was used. Screenshots/logs must omit keys, account IDs and private case data. Do not send private case records. Security-reporting boundaries are in [SECURITY.md](SECURITY.md).

The hackathon submission links must stay accessible through 21 December 2026. Do not alter linked materials after 12 November 2026 at 20:00 London until that announcement. Release assets and historical bytes are retained; do not replace published archives in place.
